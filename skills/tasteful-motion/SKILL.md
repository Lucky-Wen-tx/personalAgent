# 动效

## 输入
- 要动的那个界面或组件（文件、截图或一段描述）。
- 动效的用途：引导注意力、表达状态变化、延续空间关系，还是纯氛围。说不出用途的先别加。
- 约束：是否要管低端机和弱网、是否有触屏、有没有 `prefers-reduced-motion` 的要求。
- 和 `simple-clean-ui` 的关系：那个 skill 负责删东西，这个负责让留下的东西动得舒服。两者冲突时以删减为先——**加动效不能成为保留多余元素的理由**。

## 步骤
1. **只给会变的东西加动效**：状态切换、层级进出、位置关系改变、数据更新。静态装饰不加，那只是噪声。
2. **时长分三档**，同一元素只用一档：即时反馈 100–150ms（颜色、亮度）、状态变化 200–300ms（位移、展开、收起）、场景进入 400–700ms（元素入场）。超过 800ms 的动作要有人能说出理由。
3. **缓动统一**：进场用减速曲线（冲出去再停住），退场用加速曲线，一页里不超过两种缓动。线性缓动几乎总是错的。
4. **位移量小**：入场十几像素、hover 一两像素、按压小到几乎看不见。需要「更大的动感」时，靠透明度和层级去营造，而不是让元素飞。
5. **交错要有节制**：一组元素依次进场时间隔 40–80ms；超过六个就整组同时进来，否则最后一个出现时第一个已经过时了。
6. **入场只播一次**：滚动触发的用观察器，播完取消观察；元素默认可见，动效只决定「怎么出现」，不决定「是否出现」——脚本挂了页面也得完整。
7. **收尾两件事**：`prefers-reduced-motion` 下把时长压到几乎瞬时并去掉位移；只对 `transform`、`opacity`、`filter` 做动画，`will-change` 只在动画期间挂上。
8. **会动的不能只是好看**：过一遍它有没有让 AX 变差——动效推迟了内容可见、动画中无法点击、焦点环被盖住、状态变化只有动画没有语义。有的话先修这个，再谈手感。

## 输出格式
- 直接交付改好的文件或可替换的代码片段，不附动效说明文档。
- 需要交代时在对话里一句话说清：哪些元素动了、为什么值得动、参数落在哪一档。

## 不要做
- 不要满屏都在动：一屏里会动的东西不超过三处，同时运行的动画控制在个位数。
- 不要弹入、飞入、旋转、闪烁、视差层层叠、滚动劫持，也不要文字逐字弹出。
- 不要用动画代替反馈：加载失败不能靠抖一下表示，错误要有文字和位置。
- 不要为了动效改布局、加空 DOM 层或加包裹容器。
- 不要引入动画库（GSAP、Framer Motion、AOS 之类）。CSS 加几十行原生 JS 足够，除非用户明确要求。
- 不要让内容依赖脚本才可见，也不要在动画期间挡住交互。
- 范围外的请求（重做视觉风格、改交互流程、换框架）停下来问，不要自己发明。
